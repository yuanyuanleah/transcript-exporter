# 抖音视频采集细节

## 平台判断与工具选择

- **Mac**：`mac_computer_use_tool`，参数 `plane="bu"`，代码中 `import seed_browser_use as bu`
- **Windows**：`computer_use_tool`，参数 `plane="bu"`，代码中 `import seed_browser_use as bu`
- 两者 API 完全一致：`bu.navigate()`、`bu.wait_for_load()`、`bu.snapshot()`、`bu.get_page_text()`、`bu.find()`、`bu.click()`

## 登录检测与处理

### 登录态判断标志
- 页面顶部显示"登录"按钮 → 未登录
- 作品列表区域显示"服务异常，重新刷新拉取数据" → 未登录或登录过期
- 作品列表正常显示视频卡片（含封面、标题、点赞数）→ 已登录

### 未登录处理
1. 不要尝试自动输入手机号/验证码，抖音有滑块验证和短信验证。
2. 立即调用 `interaction.request_action`：
   ```python
   interaction.request_action(
       type="browserControl",
       display_message="抖音页面需要登录才能查看完整作品列表。请接管浏览器完成扫码或验证码登录，登录完成后把控制权交回。"
   )
   ```
3. 用户交回后，重新 `bu.snapshot()` 确认作品列表已加载。

## 采集节奏

模式、随机间隔、休息和验证码暂停策略统一读取 [主文件的采集节奏与中断](../SKILL.md#采集节奏与中断)，本文件不另设一套固定值。默认稳妥模式，用户指定快速或自定义时直接应用。

示例代码中的 `operation_delay()` 指当前模式的随机操作间隔；`time.sleep(operation_delay())` 只是操作间隔，批间长休息在 cell 外按主文件处理。示例省略验证码检测和进度持久化，实际每次导航/滚动后都应检测并按主文件暂停策略处理。

保持登录态，不反复退出重登；遇到需要手动登录/验证时暂停相关页面操作，不阻塞已有缓存的保存与交付。

## 主页视频列表提取

### 方法一：从页面文本提取（推荐）
登录后，`bu.get_page_text()` 返回的文本中包含每条视频的完整信息：
```
置顶
3091

你越强势，AI可能越蠢 很多人以为，把要求、步骤和标准...
```
- 数字 = 点赞数
- 第一行文字 = 标题 + 文案（以空格分隔）
- 视频链接需从 DOM 的 `href` 属性提取

### 方法二：从 DOM 提取视频链接
用 `bu.read_all()` 或 snapshot 中的 ref 提取所有 `/video/xxxxx` 链接：
```python
videos = bu.read_all(
    "a[href*='/video/']",
    fields=["href", "text"],
    limit=100,
)
```
- 去重：同一视频可能在"作品"和"推荐"区域重复出现，按 video_id 去重。
- 置顶视频会标注"置顶"，但不能把它的列表位置当作最新顺序。只收集当前作者作品，并按 video_id 去重；虚拟列表需每次滚动后累积读取结果。

### 按模式加载列表

单条视频直接进入详情页。最新 N 条只加载足以按真实日期确认 N 条的作品，处理置顶干扰；无法确认排序时如实标注页面顺序。

仅 Top N 模式扫描全部作品。每次滚动后积累视频 ID 和卡片信息；出现“暂时没有更多了”可标记完整。连续两轮无新增、达到本轮预算或遇到限制时停止，并记录 `scan_complete: false`，排名仅代表已加载作品，不无限滚动。

```python
import random

def operation_delay(mode="steady", custom_range=None):
    low, high = custom_range or ((2, 3) if mode == "fast" else (4, 6))
    return random.uniform(low, high)
```

`mode` 来自本任务配置，不能在示例循环中重新覆盖；用户指定每条结束后的间隔时在条目完成后等待，不把它错误地施加给每个 DOM 读取动作。

### 主页全量排序落盘（分批采集复用规范）

滚动加载全部完成后，将提取到的全部视频按点赞数降序排序，保存为本地 JSON：

```json
{
  "author": "示例博主",
  "author_key": "user_example",
  "scan_complete": true,
  "collected_at": "2026-09-25 20:00:00",
  "total": 299,
  "videos": [
    {"rank": 1, "video_id": "7635580570106408680", "url": "https://www.douyin.com/video/7635580570106408680", "title": "鬼谷子说 怎么操纵人心", "likes": 253000}
  ]
}
```

- **保存路径**：当前工作目录，优先使用 `{作者ID}_all_videos_sorted.json`，缓存中保留昵称；昵称含特殊字符时替换为下划线。旧版昵称缓存只有确认 author_key 与当前作者匹配后才复用。
- **复用规则**：用户要求"Top 1-20 / 21-40 / 41-60"等分批采集时，直接按落盘排序取对应区间，**不重新滚动扫描主页**；仅当用户明确要求最新数据或落盘文件缺失时才重扫。
- **缓存作用**：本地保存无需额外访问抖音，可减少重复扫描；不据此承诺整个采集任务无风险。
- **重扫纪律**：不要在短时间内反复滚动加载同一博主主页（批量滚动属于批量读取行为，多次高频执行才可能被识别为异常）；确需核对数据更新时，间隔数周/月低频重扫一次即可。

### 断点续采（进度文件）

以作者 ID 为主键保存进度和每条完整结果缓存。昵称用于展示；未知作者 ID 时使用规范化主页 URL。状态与重试规则以 [主文件 Step 2](../SKILL.md#step-2逐条采集并立即缓存) 为准。

```json
{
  "author_key": "user_example",
  "target_ids": ["7635580570106408680"],
  "output_key": "local:douyin_data/example_20261016_batch01",
  "mode": "steady",
  "verification": {"account_key": "local_profile_1", "date": "2026-10-16", "daily_count": 0, "recent_at": []},
  "targets": [
    {"video_id": "7635580570106408680", "status": "cached", "result_path": "example_results/7635580570106408680.json", "transcript_status": "success", "transcript_source": "web_fetch", "file_path": null, "record_id": null}
  ]
}
```

1. 合并当前目标与旧进度，保留历史状态和排序快照。每条获取结果后先原子保存完整缓存，再设为 `cached`。
2. 输出成功后记录 `record_id` 或 `file_path`，本地文件读回一次确认；飞书以成功响应/必要时批次读回为依据，再设 `done`。逐字稿确实失败时保留失败状态和原因，即使基础数据已输出。
3. 续跑跳过同目标的成功输出；缺失部分从缓存恢复。切换目标或文件丢失时重新交付缓存，不能依赖旧目标的 `done` 跳过。
4. 采集、输出、转写的失败环节分别记录；采集/写入本轮各最多重试一次，妙记每条最多一次。只修复失败部分；结果不明的创建先查已有视频 ID，不重复新增。
5. 对缓存和进度使用临时文件写入后 `os.replace`，不把正文只留在会话内；无口播和用户跳过用独立 `transcript_status` 表达，不与失败混淆。

飞书进度的 `output_key` 使用 base_token/table_id；record_id 映射按视频 ID 建立。任务内已确认成功的记录无需每条重新读表，状态不明时才批次核对。

## 视频详情页数据提取

### 页面结构
进入 `https://www.douyin.com/video/<video_id>` 后，`bu.get_page_text()` 返回：
```
00:01 / 07:57
...（章节要点，如有）
第2集 | 你越强势，AI可能越蠢 很多人以为...（完整文案）
3091
78
2177
543
举报
发布时间：2026-07-27 20:02
孟湄

粉丝4990获赞2.0万
```

### 数据字段映射
| 字段 | 提取方式 |
|------|----------|
| 标题 | 文案第一行，`\|` 或第一个空格之前的部分 |
| 介绍/文案 | 标题之后的完整文字，到互动数字之前 |
| 点赞 | 互动区第1个数字 |
| 评论 | 互动区第2个数字 |
| 收藏 | 互动区第3个数字（非必须采集） |
| 转发 | 互动区第4个数字 |
| 发表日期 | "发布时间：" 后的时间字符串 |
| 作者昵称 | 发布时间下方的作者名 |

### 数字格式处理
- 点赞/评论/转发可能显示为"1.6万"、"2.3万"等缩写。
- 转换规则：`1.6万` → `16000`，`2.3万` → `23000`。
- 小于1万的数字直接为整数。
- 写入飞书 number 字段时必须为整数，不能带"万"字。

### 批量提取效率
- 视频较多时，逐个导航+等待加载较慢。
- 可在一个浏览器 cell 中循环导航所有视频，减少 cell 调用开销：
  ```python
  import random

  for url in video_urls:
      bu.navigate(url)
      bu.wait_for_load(timeout=20)
      time.sleep(operation_delay(mode, custom_range))  # 复用本任务模式配置
      page_text = bu.get_page_text()
      # 解析并存储
  ```
- 注意 cell 超时限制（默认120秒），视频超过5条时需分批或增大 `timeout_ms`。
- 休息和验证码暂停统一按主文件执行；长任务分 cell 保存缓存和进度，避免超过工具超时。

## 逐字稿提取

唯一规则入口是 [主文件 Step 3](../SKILL.md#step-3获取逐字稿)：**完整 DOM 转录候选 → web.fetch → 可用的妙记回退**。

- DOM 只有视频介绍、章节要点或当前帧字幕时，不能作为完整逐字稿。没有完整转录区域就进入 web.fetch；不额外循环播放、截图 OCR 或下载来证明 DOM 完整。
- web.fetch 确实提供分页字段时才按返回的 `end_offset/total_length` 继续读取；不要假设所有环境结构一致。offset 不增加、重复页或调用预算耗尽则记录失败，避免无限循环。按实际内容标记定位转录正文，不固定在第一个空行截取。
- 空白、调用失败、明确截断和整段占位说明属于失败。少于 50 字、缺结尾标点只需结合来源复核；正常口播含“获取”“完整内容”“web.fetch”等词不能被删除。
- 记录 `transcript_source` 和 `transcript_status`；获取失败不能伪装成“无口播”。原视频确实无口播或用户不要逐字稿时不触发回退。
- 妙记整批计数、1–3 条自动执行、超过 3 条一次确认、依赖支持检查及失败交付，均按主文件执行，不在本文件另加首次启用审批。该路径会下载音频并上传本人飞书妙记；禁止下载/上传时跳过。

## 常见异常处理

| 异常 | 原因 | 处理 |
|------|------|------|
| 作品列表显示"服务异常" | 未登录或登录过期 | 请求用户接管重新登录 |
| 视频详情页加载超时 | 网络慢或页面暂不可用 | 重试一次，仍失败保存原因并继续其他条目 |
| 互动区数字缺失 | 页面未提供或加载不全 | 留空并记录缺失，只有页面明确为 0 才填 0 |
| 逐字稿返回为空 | 无口播或读取失败，需区分 | 已确认无口播则 not_applicable；获取失败按主文件 Step 3 统一处理 |
| 逐字稿明确截断/只有占位说明 | 分页未完成或未取到正文 | 按 Step 3 补齐或回退，失败留空并报告，不重复无限校验 |
| 页面跳转登录页 | 登录态失效 | 重新请求用户登录 |
| 人机验证（滑块/点选/验证码） | 需要人工验证 | 暂停并请求用户接管，重新读取后恢复；重复验证按主文件的账号/日期计数与暂停策略执行 |
